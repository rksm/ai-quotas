#+TITLE: ai-quotas
#+DATE: [2026-07-29 Wed]

* Idea

A Rust CLI app that monitors quotas, costs, and prepaid balances of
AI-related services.

One invocation reads a declarative YAML config, queries all configured
services and accounts in parallel, and renders the results either as a
human-readable table or as JSON.

** Core design idea

The binary ships with hard-coded provider modules, one per service. The YAML
config selects services, names accounts, supplies credentials, and can
anchor an estimated OpenAI balance. All knowledge about how to query a
service lives in exactly one Rust module.

* Services and metrics

Three kinds of metrics exist, and every provider returns a list of them:

- *Windowed quota*: percent used plus reset time (label, used_percent,
  resets_at). Raw ~used~ / ~limit~ values are carried along when the service
  provides them.
- *Balance*: remaining prepaid amount (amount, currency), also with optional
  raw values (e.g. ElevenLabs character counts).
- *Cost*: an amount spent over the period named by its label. Cost metrics
  are informational until cost-specific thresholds are added.

| Service     | Accounts | Metrics                                            |
|-------------+----------+----------------------------------------------------|
| claude-code | 2 (Max)  | 5h window, 7d window, Fable weekly window          |
| codex       | 1        | 7d window                                          |
| openai-api  | 1        | UTC month spend, estimated balance, limit headroom |
| deepgram    | 1        | prepaid balance                                    |
| elevenlabs  | 1        | credits remaining (count / limit)                  |
| runpod      | 1        | prepaid balance                                    |

Each provider fetches its full fixed metric set. There is no per-account
metric selection in the config.

* Querying strategy

Per provider, decided at implementation time:

1. *API first*: direct HTTPS calls from Rust when an endpoint works for the
   given app, quota type, and login method. For claude-code this is the
   OAuth-authenticated usage endpoint that powers the ~/usage~ screen. For
   codex it is the ChatGPT backend rate-limit endpoint. For openai-api it is
   the organization Costs API and optional hard spend-limit endpoint.
2. *CLI fallback*: spawn the vendor CLI with the account's env injected and
   parse its output, only where no workable API route exists.

If an undocumented endpoint changes, the fix lives in that one provider
module.

* Credentials

Each account entry chooses exactly one credential source:

- ~env~ contains literal values. The provider either reads the variables
  directly or injects them into a subprocess for a CLI fallback.
- ~credentials_file~ is supported for Claude Code on Linux and Windows. It
  names an absolute Claude Code ~.credentials.json~ path or one beginning
  with =~/=. The provider reads ~claudeAiOauth.accessToken~ on every fetch.

The app never caches, refreshes, or modifies a managed credential file.
Claude Code owns refresh-token rotation, and the next run or watch interval
picks up a newly written access token. OAuth expiry and malformed or missing
files are isolated as clear per-account errors. On macOS, where Claude Code
stores managed credentials in the Keychain, use the environment-token
source.

Secrets in YAML are acceptable because the app has no secret store of its
own. Protect the config and every referenced credential file accordingly.

** OpenAI estimated balance

OpenAI does not expose prepaid credit balance through its supported API.
An account can optionally record a balance copied from the billing
dashboard at a precise time:

#+BEGIN_SRC yaml
balance:
  as_of: "2026-07-29T18:00:00+02:00"
  amount: 20.00
  currency: USD
#+END_SRC

The provider calculates ~amount - costs since as_of~ and labels the result
~est-balance~. The value is an estimate because the Costs API does not
represent later top-ups, credit expiration, refunds, or other balance
adjustments. OpenAI cost reporting can also lag. Copy a fresh dashboard
balance and update ~as_of~ after any adjustment.

* Configuration

Default location ~~/.config/ai-quotas/config.yaml~, overridable with
~--config~. Unknown service keys are a config error. Account names appear in
output and JSON.

#+BEGIN_SRC yaml
thresholds:            # optional, defaults built in
  quota_warn: 70       # percent used -> yellow
  quota_critical: 90   # percent used -> red
  balance_critical: 10.0   # currency units -> red

services:
  claude-code:
    accounts:
      - name: personal
        credentials_file: ~/.claude/.credentials.json
      - name: work
        credentials_file: ~/.claude-work/.credentials.json
  codex:
    accounts:
      - name: main
        env:
          CODEX_OAUTH_TOKEN: ...
  openai-api:
    accounts:
      - name: main
        env:
          OPENAI_ADMIN_KEY: sk-admin-...
        balance:                    # optional estimate anchor
          as_of: "2026-07-29T18:00:00+02:00"
          amount: 20.00
          currency: USD
  deepgram:
    thresholds:              # per-service override
      balance_critical: 25.0
    accounts:
      - name: main
        env:
          DEEPGRAM_API_KEY: ...
  elevenlabs:
    accounts:
      - name: main
        env:
          ELEVENLABS_API_KEY: ...
  runpod:
    accounts:
      - name: main
        env:
          RUNPOD_API_KEY: ...
#+END_SRC

Threshold defaults: quotas turn yellow at 70% used and red at 90%. Balances
turn red below $10. ElevenLabs credits turn red below 10% of the plan limit
(the limit is known there).

* CLI surface

#+BEGIN_SRC text
ai-quotas [--config PATH] [--json] [--watch] [--interval SECS]
          [--service NAME]... [--account NAME]...
#+END_SRC

- Default run: fetch everything in parallel, print the table, exit.
- ~--service~ / ~--account~ are repeatable filters. Only selected accounts
  are fetched, unneeded network calls are skipped.
- Exit codes: 0 all accounts fetched, 1 at least one account errored,
  2 config or usage error.

* Human-readable output

A table grouped by service and account. Service and account render once as a
header line, the account's metrics are grouped beneath it so one account
reads as one block.

#+BEGIN_SRC text
claude-code  personal
  5h            42% ████░░░░  resets 14:00 (in 2h 10m)
  7d            71% ██████░░  resets Thu 09:00 (in 1d 19h)
  fable-week    12% █░░░░░░░  resets Mon 00:00 (in 4d 10h)
claude-code  work
  5h             3% ░░░░░░░░  resets 14:00 (in 2h 10m)
codex        main
  7d            55% ████░░░░  resets Fri 12:00 (in 2d 22h)
openai-api   main
  est-balance   $19.42 remaining
  month-spend   $9.20 spent
deepgram     main
  balance       $102.10 remaining
elevenlabs   main
  credits       81,203 / 100,000 remaining
runpod       main
  balance       $435.85 remaining
#+END_SRC

- Usage bars plus percent for windowed quotas, plain amounts for balances
  and costs.
- Reset times as local time plus relative duration.
- Color when stdout is a TTY, plain text otherwise. Metrics past the warn
  threshold render yellow, past the critical threshold (little quota or
  money left) render red.

* Watch mode

- ~--watch~ with ~--interval~ (default 300 seconds).
- Clear screen, re-render the same table, footer line with
  ~last updated 14:32:07, next in 300s~.
- If one account's fetch fails mid-watch, keep its last known values,
  dimmed, with an error marker and data age
  (~claude-code/work: stale 5m, auth error~). One flaky endpoint never
  blanks the dashboard or kills the loop.

* JSON output

~--json~ emits one document with stable field names, a flat list of
service+account entries for easy ~jq~ consumption. Combined with ~--watch~
it emits one document per interval as JSONL.

#+BEGIN_SRC json
{
  "generated_at": "2026-07-29T14:32:07+02:00",
  "services": [
    {
      "service": "claude-code",
      "account": "personal",
      "status": "ok",
      "metrics": [
        {
          "kind": "window",
          "label": "5h",
          "used_percent": 42.0,
          "used": null,
          "limit": null,
          "resets_at": "2026-07-29T14:00:00+02:00",
          "level": "ok"
        }
      ]
    },
    {
      "service": "claude-code",
      "account": "work",
      "status": "error",
      "error": "auth token expired",
      "metrics": []
    }
  ]
}
#+END_SRC

- Per-entry ~status~ / ~error~ so one broken account does not poison the
  document.
- ~level~ (~ok~ / ~warn~ / ~critical~) is included so consumers get the
  threshold evaluation for free. Threshold logic has one home.

* Implementation

Deliberately boring stack:

- *tokio + reqwest*: one async task per account, ~join_all~, 30 second
  per-fetch timeout
- *serde / serde_yaml / serde_json*: config and output
- *clap*: CLI surface
- Provider trait ~fetch(account) -> Result<Vec<Metric>>~, one
  module per service. The whole app is: read config, fan out fetches,
  render.
- Plain ANSI colors and manual table rendering, no TUI crate
- Nix flake dev shell plus justfile (~just run~, ~just watch~, ~just test~)

* Further cost monitoring

OpenAI organization month spend establishes the cost metric. Other provider
cost APIs can return the same metric without changing configuration or
account selection. Cost-specific warning thresholds remain deferred until a
provider exposes a useful budget or limit.
