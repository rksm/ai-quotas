#+TITLE: ai-quotas

Monitor quota windows, costs, and prepaid balances for configured AI
service accounts.

* Build and run

The development environment is provided by the Nix flake.

#+BEGIN_SRC shell
direnv allow
just check
just run --config path/to/config.yaml
just watch --config path/to/config.yaml
#+END_SRC

Without ~--config~, the CLI reads
~~/.config/ai-quotas/config.yaml~. See [[file:docs/IDEA.org][docs/IDEA.org]] for
the complete configuration shape and command-line interface.

* Install with Nix

Install directly from GitHub:

#+BEGIN_SRC shell
nix profile install github:rksm/ai-quotas
#+END_SRC

To consume the package from another flake:

#+BEGIN_SRC nix
{
  inputs.ai-quotas.url = "github:rksm/ai-quotas";

  outputs = { nixpkgs, ai-quotas, ... }: {
    nixosConfigurations.example = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [{
        environment.systemPackages = [
          ai-quotas.packages.x86_64-linux.default
        ];
      }];
    };
  };
}
#+END_SRC

The configuration can contain literal credentials or paths to
credential files. Restrict its filesystem permissions accordingly.

* Credential requirements

| Service     | Credential source                                 | Requirement |
|-------------+---------------------------------------------------+-------------|
| claude-code | ~credentials_file~                                | Claude Code: ~claudeAiOauth.accessToken~. CLIProxyAPI: top-level ~access_token~. The token needs the ~user:profile~ scope. |
| claude-code | ~env.CLAUDE_CODE_OAUTH_TOKEN~                     | A full OAuth access token with the ~user:profile~ scope. A ~claude setup-token~ token is normally inference-only and cannot read usage. |
| codex       | ~credentials_file~                                | Codex: ~tokens.access_token~ and optional ~tokens.account_id~. CLIProxyAPI: the same fields at the top level. |
| codex       | ~CODEX_OAUTH_TOKEN~, optional ~CODEX_ACCOUNT_ID~  | The managed-login access token. Set the account ID for reliable routing when the login belongs to multiple workspaces. |
| codex       | ~CODEX_ACCESS_TOKEN~                              | An ~at-~ personal access token. The CLI discovers its ChatGPT account ID. |
| grok        | ~credentials_file~                                | Grok CLI: an account entry with ~key~. CLIProxyAPI: top-level ~access_token~. |
| grok        | ~env.GROK_OAUTH_TOKEN~                            | A Grok OAuth access token. |
| deepgram    | ~DEEPGRAM_API_KEY~                                | A project-scoped key with ~project:read~ and ~billing:read~. |
| elevenlabs  | ~ELEVENLABS_API_KEY~                              | A key that can read the user subscription, normally with ~user_read~. |
| runpod      | ~RUNPOD_API_KEY~                                  | A Runpod API key permitted to read GraphQL account data. |
| openai-api  | ~OPENAI_ADMIN_KEY~                                | An organization Admin API key. The provider reads current UTC month costs and an optional hard spend limit. |
| openrouter  | ~env.OPENROUTER_MANAGEMENT_KEY~                    | An OpenRouter management key. |
| openrouter  | ~credentials_file~                                | A file that contains only the raw OpenRouter management key. |
| assemblyai  | ~credentials_file~                                | A file that contains only the ~Cookie~ header of a dashboard login session. |
| assemblyai  | ~env.ASSEMBLYAI_DASHBOARD_COOKIE~                 | The ~Cookie~ header of a dashboard login session. |

Each account must configure exactly one of ~env~ or ~credentials_file~.
Claude Code, Codex, Grok, OpenRouter, and AssemblyAI support credential
files. A local path must be absolute or start with =~/=. The provider
rereads the file for every fetch. ~ai-quotas~ never modifies or refreshes
it. OpenRouter files contain the raw management key. AssemblyAI files
contain the raw ~Cookie~ header. The provider ignores surrounding
whitespace in both.
CLIProxyAPI auth files store ~access_token~ at the top level. Grok CLI auth
files store ~key~ inside an account entry. Codex auth files can also store
~account_id~ at the top level.

A credential file can also live on another machine. An scp-style reference
such as ~agent-1:.claude/.credentials.json~ reads the file over SSH on
every fetch. The host part is any SSH destination, including ~user@host~
and =~/.ssh/config= aliases. A relative remote path resolves against the
remote home directory. SSH runs non-interactively (~BatchMode~), so the
host must authenticate through keys or an agent.

Codex stores its managed credentials in ~~/.codex/auth.json~ by default.
For separate Codex homes, point each account at the corresponding
~auth.json~ file.

Grok stores its managed credentials in ~~/.grok/auth.json~ by default. The
provider reports the weekly credits window from the Grok billing service.

Claude Code stores managed credentials in the macOS Keychain rather than a
JSON file. Use the environment-token source on macOS.

OpenRouter reports the live USD credit balance and spend for the last 1, 7,
and 30 completed UTC days. The [[https://openrouter.ai/docs/api/api-reference/credits/get-remaining-credits][credits endpoint]] and
[[https://openrouter.ai/docs/api/api-reference/analytics/get-user-activity-grouped-by-endpoint][activity endpoint]] both require a management key:

#+BEGIN_SRC yaml
services:
  openrouter:
    accounts:
      - name: personal
        env:
          OPENROUTER_MANAGEMENT_KEY: sk-or-v1-...
      - name: work
        credentials_file: ~/.config/openrouter/management-key
#+END_SRC

OpenRouter may expire unused credits after one year, but its API does not
return credit purchase or expiration dates. The output cannot show those
dates. See the [[https://openrouter.ai/docs/faq][OpenRouter FAQ]].

AssemblyAI reports the USD account balance shown on the dashboard Billing
page. The AssemblyAI API has no balance endpoint, and an API key cannot read
the balance. The provider calls the undocumented endpoint behind the Billing
page instead. That endpoint needs the ~Cookie~ header of a browser login
session:

1. Log in to the [[https://www.assemblyai.com/dashboard][AssemblyAI dashboard]].
2. Open *Workspace* > *Settings* > *Billing*.
3. Open the browser developer tools and select the *Network* tab.
4. Reload the page.
5. Select the ~balance~ request.
6. Copy the value of its ~cookie~ request header.
7. Save the value in a file that only your user can read.

Point the account at that file:

#+BEGIN_SRC yaml
services:
  assemblyai:
    accounts:
      - name: main
        credentials_file: ~/.config/assemblyai/dashboard-cookie
#+END_SRC

The login session expires after some time. The provider then reports an
expired credential. Log in again and copy a fresh ~cookie~ header.
AssemblyAI can change or remove the endpoint without notice.

The OpenAI administration API exposes costs and spend limits, not remaining
prepaid credit. The provider reports current UTC calendar-month spend. If
the organization has a hard monthly spend limit, it also reports the
remaining limit headroom. See the [[https://developers.openai.com/cookbook/examples/completions_usage_api][OpenAI Usage and Costs API example]].

The exact prepaid balance remains available only in the
[[https://platform.openai.com/settings/organization/billing/credit-grants][OpenAI billing dashboard]].

An OpenAI account can optionally anchor an estimated balance to a value
copied from that dashboard:

#+BEGIN_SRC yaml
balance:
  as_of: "2026-07-29T18:00:00+02:00"
  amount: 20.00
  currency: USD
#+END_SRC

The provider subtracts costs since ~as_of~ and reports the result as
~est-balance~. Update the anchor after a top-up, credit expiration, refund,
or other balance adjustment. The estimate can briefly lag because OpenAI
cost reporting is not immediate.

* Output and exit status

The default output is a grouped table. ~--json~ emits one JSON document.
With ~--watch~, human output refreshes in place and JSON output becomes
JSONL.

- Exit 0 means every selected account fetched successfully.
- Exit 1 means at least one selected account failed.
- Exit 2 means the command or configuration was invalid.
